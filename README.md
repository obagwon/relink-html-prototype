# RE:LINK — HTML Gameplay Prototype

졸업작품으로 기획 중인 3인칭 퍼즐 어드벤처 **RE:LINK**의 시스템 검증용 웹 프로토타입이다. 문서를 보여 주는 웹페이지가 아니라, 플레이어가 직접 3D 공간을 걷고 카메라를 돌리며 세 능력을 환경에 사용해 실제 이동 경로를 만드는 플레이어블 빌드다.

이 프로토타입은 그래픽 완성도보다 다음 질문을 검증한다.

- 카메라 기준 3인칭 이동과 점프가 자연스러운가?
- 플레이어 주변을 공전하는 세 구체와 능력 전환이 명확한가?
- RE:BLOOM / RE:FREEZE / RE:PULSE가 서로 다른 사고를 요구하는가?
- 능력 사용 결과가 다리, 발판, 경사로, 문처럼 실제 공간 변화로 이어지는가?
- 두 능력 및 세 능력의 순차 조합이 읽히는가?
- 허브 → 지역 → 랜드마크 → 복원이라는 흐름이 작동하는가?

## 실행 방법

빌드 과정과 패키지 설치가 필요 없다. Three.js 0.185.1을 `vendor/`에 포함했다.

```bash
python -m http.server 8000
```

그다음 브라우저에서 `http://localhost:8000`을 연다. 다른 방법으로는 `npx serve`도 사용할 수 있다. `file://`로 HTML을 직접 여는 방식은 ES Module 보안 정책 때문에 권장하지 않는다.

## 조작법

| 입력 | 동작 |
|---|---|
| `WASD` | 카메라 방향 기준 이동 |
| 마우스 | 3인칭 카메라 회전 |
| `Space` | 점프 |
| `Shift` | 달리기 |
| `1` / `2` / `3` | RE:BLOOM / RE:FREEZE / RE:PULSE 선택 |
| 마우스 왼쪽 | 화면 중앙 대상에 현재 능력 사용 |
| 마우스 휠 | 능력 순환 |
| `E` | 포털, 조각, 귀환 지점 상호작용 |
| `R` | 현재 지역 퍼즐 리셋 |
| `Esc` | 포인터 해제 및 일시정지 |
| `F1` | 디버그 패널 토글 |
| `F2` / `F3` / `F4` / `F5` | 허브 / 생명 / 정지 / 기계 지역 이동 |

## 구현된 시스템

- WebGL 렌더러, 조명, 안개, 그림자, 반응형 리사이즈
- 작은 인간형 플레이스홀더 캐릭터와 걷기 팔다리 애니메이션
- 카메라 방향 기준 이동, 달리기, 점프, 중력, 낙하 복귀
- AABB 기반 안정적인 지형 충돌과 동적 발판 탑승 이동
- 부드러운 3인칭 카메라 추적 및 360도 마우스 회전
- 실제 3D 오브젝트로 공전하는 세 능력 구체
- 선택 구체의 확대·발광·전방 이동과 능력 빔 피드백
- 중앙 크로스헤어 기반 레이캐스트와 대상 emissive 하이라이트
- `Interactable`의 능력 허용 목록, 상태, `onBloom`/`onFreeze`/`onPulse`에 대응하는 재사용 구조
- 상태 조건을 판정하는 `PuzzleSystem`
- WebAudio 기반 능력별 임시 효과음과 클리어 음
- F1 디버그, 지역 워프, 지역 리셋, 낙하 시 안전 복귀
- Bloom / Freeze / Pulse 완료 상태의 `localStorage` 저장
- 조각 복원에 따른 허브 슬롯·빛·식생 변화

## 지역과 퍼즐

### 중앙 허브

부서진 세계의 핵, 세 조각 슬롯, 세 지역 포털을 배치했다. 허브에서 실제 월드에 배치된 세 방향의 지역 실루엣을 볼 수 있고, 획득한 조각에 따라 중앙 핵과 주변 식생이 밝아진다.

### RE:BLOOM — 생명의 지역

최신 생명 지역 수정본과 필드 맵의 강·절벽·고저차·거대한 죽은 나무 구성을 우선 반영한 Vertical Slice다.

1. **시든 덩굴 다리**: BLOOM으로 성장해 충돌이 있는 다리가 된다.
2. **꽃 점프대**: BLOOM으로 개화하고 플레이어를 높은 지형으로 튕긴다.
3. **움직이는 잎사귀**: 물살 위를 움직이는 잎을 FREEZE해 동적 발판으로 사용한다.
4. **성장 + Freeze 경사로**: BLOOM 중 형태 변화를 관찰하고 FREEZE해 계단형 경사로로 고정한다.
5. **죽은 나무의 세 뿌리**: 직접 복원, 바위 밀기, BLOOM → FREEZE 조합을 완료하면 실제 입구가 열린다.
6. **생명의 심장 테스트룸**: BLOOM → FREEZE → PULSE 순서로 식물 전도 경로를 완성해 생명의 조각을 복원한다.

### RE:FREEZE — 정지의 지역

최신 필드 구성안의 랜드마크인 **붕괴 중인 공중정원/부유 유적**을 사용한다.

1. **떨어지는 파편**: 적절한 높이에서 FREEZE해 발판으로 만든다.
2. **회전 석판**: 수평 순간을 고정해 다리로 만든다.
3. **PULSE + FREEZE 부유 발판**: 멈춘 장치를 작동시킨 뒤 필요한 위치에 고정한다.
4. **폭포 Freeze**: 흐르는 폭포를 얼음벽 형태의 보조 이동 구조로 바꾼다.
5. 세 대표 퍼즐을 완료하고 실제 부유 유적 상단에 도착하면 정지의 조각을 복원할 수 있다.

### RE:PULSE — 기계의 지역

황갈색 석조, 황금 룬, 고대 마도기계, 쓰러진 거인을 사용하며 현대 공장 표현은 배제했다.

1. **룬 기둥 연결**: 세 중계기의 방향을 회전시켜 에너지의 시각적 경로를 완성한다.
2. **BLOOM + PULSE 전도 덩굴**: 끊어진 두 단자를 식물로 연결하고 그 경로에 에너지를 흘린다.
3. **부유 석판**: PULSE로 움직인 석판을 FREEZE해 협곡 발판으로 사용한다.
4. **거인의 팔**: PULSE로 관절을 움직인 뒤 수평 순간에 FREEZE해 다리로 사용한다.
5. 모든 경로를 복구한 뒤 거인의 심장에 PULSE를 사용하면 기계의 조각이 복원된다.

## 기획서 대비 구현 범위

구현한 핵심은 3인칭 이동, 점프, 카메라, 공전 구체, 능력 선택과 조준, 능력별 상태 변화, 단독 퍼즐, BLOOM → FREEZE, PULSE → FREEZE, BLOOM → PULSE, BLOOM → FREEZE → PULSE, 세 지역 랜드마크, 허브 복원, 지역 이동, 리셋과 저장이다.

기획 충돌 시 요청된 우선순위에 따라 최신 수정본과 세부 지역안을 적용했다. 따라서 정지 지역의 필드 랜드마크는 초기 전체 기획안의 얼음 성보다 최신 필드안의 공중정원을 우선했다. 과거 LIFE / FREEZE / ACTIVATE 표기는 모두 현재 명칭인 RE:BLOOM / RE:FREEZE / RE:PULSE로 통일했다.

## 의도적으로 생략한 요소

- 세 던전의 전체 1F/B1/B2 또는 1F/2F/3F 구성
- 최종 보스전, 컷신, 대사, 엔딩, 수집 콘텐츠
- 덩굴 진자 잡기, 실제 썰매 활강, 낙하물 간 실제 물리 충돌
- 정지 지역의 반사경 3개 빛 퍼즐과 대규모 공중 파편 상승
- 기계 지역의 제한 전력 재분배 신전과 작은 골렘 유도
- 적, 전투, 체력, 체크포인트 UI
- 외부 모델·텍스처·음원 및 최종 그래픽

이 항목들은 핵심 조작과 상태 조합 검증을 흐리지 않도록 다음 제작 단계 대상으로 남겼다.

## 알려진 제약 및 버그 가능성

- 충돌은 물리 엔진이 아닌 AABB와 결정론적 애니메이션을 사용하므로 회전 물체의 모서리 판정이 실제 형태보다 넓을 수 있다.
- 카메라는 벽을 피하는 별도 충돌 처리가 없어 큰 오브젝트에 가까이 붙으면 잠시 내부가 보일 수 있다.
- FREEZE 타이밍 허용 범위는 프로토타입 테스트를 위해 넓게 설정했다.
- 모든 지역을 하나의 Three.js 씬에 유지하므로 최종 에셋으로 교체할 때는 지역별 로딩/언로딩이 필요하다.
- 모바일 입력은 지원하지 않는다.
- 브라우저 정책상 소리는 `START PROTOTYPE`을 누른 뒤 활성화된다.

## 테스트

Chrome 헤드리스 WebGL 환경에서 다음 자동 스모크 테스트 17개를 실행해 모두 통과했다.

- 씬 초기화, 충돌 월드, 세 구체, 상호작용 레지스트리
- 카메라 기준 이동, 확장된 점프 거리, 360도 카메라, 1/2/3 능력 전환
- 중앙 크로스헤어 레이캐스트와 지역 퍼즐 리셋
- BLOOM 성장, FREEZE 정지
- BLOOM → PULSE
- BLOOM → FREEZE → PULSE
- 허브와 세 지역 이동
- localStorage 저장

개발용으로 `http://localhost:8000/?smoke=1`을 열면 동일한 테스트가 격리 실행되며, `window.RELINK.runSelfTest()`로 수동 호출할 수도 있다.

## Unity로 옮길 때 참고할 구조

- `Interactable` → `MonoBehaviour` 기반 환경 상호작용 컴포넌트
- `abilities` → 능력 플래그 또는 인터페이스(`IBloomable`, `IFreezable`, `IPulseable`)
- `state`와 handler → Animator/상태 머신 + 능력 이벤트
- `PuzzleSystem` → 퍼즐별 조건 목록과 완료 이벤트를 가진 ScriptableObject 또는 PuzzleController
- 결정론적 `update()` 애니메이션 → Timeline, Animator, DOTween 또는 직접 보간
- `World`의 collider 목록 → Unity Collider/CharacterController와 MovingPlatform 컴포넌트
- `localStorage` 진행도 → 직렬화 가능한 SaveData의 지역 조각 Boolean

능력의 시각 효과와 퍼즐별 메시 코드는 바뀌어도, **대상 속성 → 상태 전이 → 완료 조건 → 공간 변화**의 데이터 흐름은 그대로 옮길 수 있다.
